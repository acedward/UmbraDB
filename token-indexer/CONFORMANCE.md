# MIP-0018 conformance of the UmbraDB token indexer

Every MUST and SHOULD sentence of the final MIP-0018 text, mapped to the UmbraDB tests that cover it, or "not
applicable" with the reason. UmbraDB is a consumer and indexer: rules for emitters, contracts and future MIPs are
listed and marked not applicable.

## What changed from the reference matrix (`78ecbb4` → `274a84f`)

| `274a84f` row | Reference row (`78ecbb4`) | Change |
|---|---|---|
| C-014 | C-014 | Rewritten: a Null record deletes **its field** ("MUST stop serving the field's value and its earlier values, and MUST NOT fall back to an earlier value"); before, a Null withdrew the whole identity. UmbraDB keeps its own versions of S1a, S3a–S3d, S4a/S4b, S9d (the reference vectors stay on `78ecbb4`, owner Q16–Q18). |
| C-015 | — | New: once its last field is deleted, an identity MUST NOT be referenced at all — in listings, lookups, groups or metadata history. |
| C-025 | C-024 | "group **visible** token identities" → "group token identities" (an identity without fields no longer exists). |
| C-016 … C-036 | C-015 … C-035 | Renumbered (one row inserted); texts unchanged. |

## How to read a row

- **Vectors**: run by the vendored reference runner through UmbraDB's two adapters — the pure state module
  (`[[mip0018.vectors.pure-adapter]]`, `[[mip0018.vectors.runner-cli]]`) and the real Postgres path
  (`[[mip0018.vectors.pg-adapter]]`, `[[mip0018.vectors.pg-runner-cli]]`): 59 reference normative vectors, 43
  informative vectors and UmbraDB's 8 own versions. `*` marks UmbraDB's own `274a84f` version of a vector
  (`token-indexer/mip0018/vectors-umbradb/`), used instead of the vendored `78ecbb4` one.
- **Stagenet**: the twelve recorded cases (C01–C10, IDX, U1; recorded fixtures, CI) — see sub-plan D's coverage table.
- **Tests**: `[[…]]` is a governed test id of the required gate (`test/integration/required-tests.manifest.json`).
- **Status**: `covered` (the tests listed pass in the required gate) or `not applicable` (with the reason).
